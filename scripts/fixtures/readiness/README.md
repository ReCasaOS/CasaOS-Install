# Fixtures of the readiness proof

`<leg>/<step>.json` is the `data` of `GET /v1/sys/os/readiness` as the core itself makes it, `NewAnswer(Run(ctx, probe, Options{}))` of `pkg/osreadiness` (core branch `feat/os-readiness`, commit cac01b3a9f8f): `clean.json` for the box the proof installs (a cloud image with ReCasaOS, Docker and the four witness containers) and one file for each step of the dirty matrix, the box dirtied the way `os-readiness-proof.sh` dirties it. `d11` is Debian 11 (Docker 28.0.4 with a 29 on offer), `u22` is Ubuntu 22.04.

They were dumped by `dump_readiness_test.go.txt`: copy it as `pkg/osreadiness/zz_dump_test.go` into a `git archive` copy of the core (with its gitignored `codegen/` folder) and run `FIXTURE_OUT=<dir> go test -count=1 -run TestDumpReadinessFixtures ./pkg/osreadiness/`. The probe is the core's own fake one (`fake_test.go`), made to look like the proof's guest: the shape, the codes, the severities, the data and the texts are the core's, what the real tools print on a real guest is not here and is what the VM legs show. When the core's checks change, dump them again: `test-os-readiness-proof.py` reads these files for every answer of a healthy leg.
