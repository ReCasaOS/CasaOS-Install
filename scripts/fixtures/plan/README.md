# Fixtures of the plan proof

Each `*.json` is a whole answer of the core (the envelope `{success, message, data}`, as the route puts it) for `GET /v1/sys/os/upgrade/plan`, `POST /v1/sys/os/upgrade/plan` and `GET /v1/sys/os/upgrade/runbook`, as the core makes it: the plan, the failures and the runbook are what `pkg/osplan` makes of the measured Debian 11 box (the first core release that has these routes: make them again whenever its contract changes, see the end), and the envelope is the one `route/v1/system_os_plan.go` and `service/system_os_plan.go` put around them.

| file | what it is |
|---|---|
| `plan-needs_acceptance.json` | GET, a job that is done: the plan of the measured box (fuse was put there by hand, libsemanage1 by apt: the owner has to accept the removal of fuse). The real fixtures of the measurement (`sandbox-paused-*.txt`, the sources of the Debian 11 cloud image with Docker's file) go through the real parser, rewriter and judge. Its `plan_id` is the golden one of the core's tests |
| `plan-ok.json` | the same box with fuse put there by apt too: nothing to accept |
| `plan-downgrade.json`, `plan-kept_back_unlisted.json`, `plan-kept_back_silent.json`, `plan-estimates_unknown.json`, `plan-lowroom.json`, `plan-disk_unknown.json`, `plan-conf_reasons.json` | GET, a job that is done, for what a clean box does not give: the plan the core makes of the real output of apt in its `testdata/real` for a downgrade (`downgrade`, blocked), for a package on hold that apt counts as not upgraded and does not name (`dist_kept_back` with `names: []` and `unlisted: 1`: the count of the plan is more than its list), for a package that the minimal upgrade keeps back and the full upgrade names in no list and counts nowhere (`dist_kept_back` with `names: ["osp-k"]` and no kept back package behind it: the problem alone names it), for sizes that apt did not say (`disk_note: estimates_unknown`, no disk rows), for a room that could not be read (`unknown: true` in the row, with `free: 0`, and in the `disk_short` problem, which has no `free`) next to one that was read and is short, for an estimate that apt ends for lack of room in the sandbox's cache (`E: You don't have enough free space in <sandbox>/cache/archives/.` after the two sentences of sizes: the sizes are true, `estimates.known` and the disk rows are there, and `disk_short` blocks), and of a box with a file of apt's configuration for each of the six reasons one is left out for (`not_simple`, `has_directive`, `not_allowed_setting`, `too_large`, `not_regular`, `proxy_auto_detect`), a proxy of one host that is kept, the option of gpgv in a fragment whose name has a colon (left out), one with a colon that is kept (not named) and a directory of apt.conf.d (not named). The report takes that shape as valid, and holds the sizes of nothing against the leg's own box, which has hundreds of packages to upgrade |

| `plan-left_behind.json`, `failed-left_behind.json` | GET, a job that is done and one that failed, and the core could not remove the sandbox's directory: the status says it in `sandbox_left_behind` (the full path of the directory) |

The detail of `sources_target` says where the way back is for a box whose sources an earlier try of the hop by hand already rewrote (the restore script in that plan's folder of `/var/backups`, and what to do when the upgrade has begun there): it is a line of more than 200 characters, which the report allows for the failures of the sources, while the words of apt stay cut at 200. The failures of the sources, and the other codes of the core, carry neither key |
| `refused-busy.json`, `refused-no_room.json` | the 409 of the POST that is refused at once |
| `no_plan-<reason>.json` | the 409 of the runbook when there is no plan to write it from |
| `conf-inputs.json`, `conf-cases.json` | files of apt's configuration (the core's own cases of its grammar, and the ones of the proof's harness, each as hex), and what the core's grammar says of each: the reason it leaves the file out of the sandbox, or `""` when it keeps it, and the text it writes again. The proof's own grammar has to say the same of every one of them. `conf-settings.json` is the allow-list as the core holds it (`sandboxAptSettings`), which the copy in the report is held against, entry by entry. `conf-inputs.json` has the files written by hand (the first ones) and the GENERATED ones (names that start with `generated: `, made by `gen_conf_inputs.py`: every method and setting that the allow-list has or lacks, the proxy of one host against a row of hosts, the settings of `Acquire::` itself, the whole names, values and shapes of line, bytes that are not UTF-8, and a few hundred files of pieces put together by chance from a fixed seed), `conf-cases.json` is dumped. The harness holds the report's grammar against the core's on every one, and says that the cases are of the inputs |
| `sources-cases.json` | the sources of boxes of six shapes (the measured one, comments and blanks and a comment after a line, backports and the archive's host and non-free, options and a line of Docker's inside sources.list, files of sources.list.d, no sources.list at all) as the core's `RewriteSources` rewrote them: the files and their lines, what is put aside, the tree, the counts and both hashes. The proof's own computation of the sources has to agree with every one of them |

The apt.conf.d of the box is the one of the Debian 11 cloud image of the measurement (`os-upgrade-measure-d11-12`, `sources-before.txt`), which has no `15update-stamp`. The sandbox keeps a file of apt's configuration only when every line of it is blank, a `//` comment or one statement `NAME "VALUE";` with NAME on the allow-list of the core (`sandboxAptSettings`: for each download method what its program reads, which for http and https is `Proxy`, `Timeout`, `Pipeline-Depth`, `Dl-Limit`, `Max-Age`, `No-Cache` and `AllowRedirect`, and for ftp `Proxy` and `Timeout` only (its program reads no more: the strings of its binary in apt 2.2.4 and 2.6.1), and for the three `Proxy::<host>`, the proxy of one host such as `Acquire::http::Proxy::deb.debian.org`; for `Acquire::` itself `Retries`, `Languages`, `PDiffs`, `By-Hash`, `Check-Valid-Until`, `ForceIPv4`, `ForceIPv6` and `Queue-Mode`; and APT::Install-Recommends and APT::Install-Suggests; names are read in any case, in ASCII; a name that runs a program, `Proxy-Auto-Detect`, has a reason of its own), and writes it again in that one form. The rest of `Acquire::` is not on it: `Acquire::gpgv::Options::0 "--log-file=<a file>"` makes the gpgv that apt runs as `_apt` write that file wherever it is told (run for real in a Debian 11 chroot: the sandbox's own `apt-get update` made `/var/lib/apt/lists/partial/osp-canary` in the box's own lists), and the third canary step of the leg proves that the plan leaves it out. all six fragments of the image have something else in them (a brace block, a setting that is not on the list), so all six are left out of the sandbox and the plan names each of them with its reason (`apt_conf_left_out`, a list of `{file, reason}`, at most 200: `01autoremove` not_simple, `01autoremove-kernels` not_allowed_setting, `20auto-upgrades` not_allowed_setting, `20listchanges` not_simple, `50unattended-upgrades` not_simple, `70debconf` not_simple). The text of `50unattended-upgrades` is shortened and has the word dpkg in it, as the real one does.

What is not the core's: the sizes of the sandbox (`sandbox.bytes` is 487 here, the fixture's fake files; the proof's harness sets realistic ones), the times (the fake clock of the core's tests), and everything that depends on what a real machine, apt 2.2.4 and the mirrors say. That is what the VM leg shows.

## How they were made, and what to run when the core changes

Nothing in them is written by hand. A throwaway test, put into the core's `pkg/osplan` for the run and not kept in any repository, built the measured Debian 11 box out of the core's own test helpers (its fake files and the real output of apt in `testdata/real`), ran the core's `Run`, `RewriteSources` and the runbook writer over it and over the boxes that make each failure, put every answer in the envelope of the route, and wrote it here as JSON. The same run wrote `conf-cases.json` and `conf-settings.json` from the core's grammar and allow-list, for the files of `conf-inputs.json`. The test is not in this repository because it needs helpers that are private to the core's tests (the box, the fake sandbox, the canonical form of a file of apt's configuration), so nothing here could compile or vet it.

When the core changes what it answers (a field of the plan, a code or a text of a problem or a failure, the grammar or the allow-list of apt's configuration, the text of the runbook, the way the sizes are read out of apt), make the fixtures again from the core's final commit, in this order:

1. `python3 scripts/fixtures/plan/gen_conf_inputs.py`, only when the files of `conf-inputs.json` have to change (it writes the same generated files every time).
2. Take a `git archive` of the core at that commit (`git archive <commit> pkg go.mod go.sum`), add the throwaway test to its `pkg/osplan` as described above, run it with `FIXTURE_OUT=<this directory>` and `CONF_INPUTS=<this directory>/conf-inputs.json`, copy what it wrote into this directory, and delete the test again.
3. Run `python3 scripts/test-os-plan-proof.py` (`REPORT_ONLY=1` for the report alone). It holds the report's grammar, its computation of the sources and its reading of the runbook against what was dumped, and it says which fixture no longer matches.

Read the diff of the fixtures before committing it: it is the change of the contract. The ones that follow the text of the runbook are `runbook.json` and `runbook-rich.json` (and the byte count in the row of `runbook.json` above); the ones that follow how the sizes are read out of apt are the `plan-*.json` that hold `estimates` and `disk`.
